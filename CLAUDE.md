# CLAUDE.md

## Working style

- Implement, don't propose. Don't wait for "yes go".
- Write idiomatic, typed Python (mypy/ruff clean). Prefer clean design patterns over cleverness.
- Imports: sorted stdlib → third-party → local, explicit (never `from x import *`), never inside a function (only exception: circular imports).
- Comments only where the logic isn't obvious — which should be rare. **Never remove human-authored comments** (TODO/FIXME/NOTE/explanatory); only remove comments you added yourself.
- **Fail fast**: bugs (wrong type, missing key, unexpected `None`) crash; runtime conditions (missing file, bad user input) are handled. Never `try/except` into a silent `None`. Catch broad exceptions only at the outermost GUI boundary.
- Test/debug scripts live in `tests/`, never the project root. Prefix ad-hoc debug scripts `_test_` so pytest skips them.
- Docs/docstrings: don't name individuals (Poppy, Freddy, Ivy).
- After major design changes, update this file.
- Claude Code may change any file in this repo.

## Project Overview

EthoGraph is a GUI for labelling start/stop times of animal movements, paired with a workflow using action-segmentation transformers to predict segments. It loads NetCDF/NWB/pynapple datasets and displays synchronized video/audio/ephys.

```python
import ethograph as eto
dt = eto.open("data.nc"); dt = eto.from_datasets([ds1, ds2])
time = eto.get_time_coord(da); data, filt = eto.sel_valid(da, kwargs)
```

## Hard Rules

**Never hardcode rates.** No frame rates (30 fps), sample rates (44100 Hz), or 1-second fallbacks for windows/trial durations — not even as fallbacks. Use source metadata (`video.fps`, `ImageSeries.rate`, audio rate) or user settings; if unknown, raise or return `None`.

**Never hardcode a device.** `resolve_device()` picks CUDA → MPS → CPU.

**Never special-case a `dataset_key` in GUI code** — put per-dataset settings in `DATASETS` metadata.

**Never call `QFileDialog` directly** — go through `gui/file_dialogs.py` (`browse_open_file` / `browse_open_dir` / `browse_save_file`). A bare dialog opens in the process's working directory, which is never where the data is; the helpers start at the caller's `preferred_dir` (the loaded dataset, the field's current value) and otherwise at `app_state.last_browse_dir` — SCOPE_GLOBAL, so the cover page's browse buttons land where the *previous session* left off, before any dataset exists. Every helper records what was picked. The wizard tabs still use raw dialogs (they hold no `app_state`).

## Architecture

### Two data-source layers

**Rendering** (`io/plot_sources`) — `PlotSource` protocol (`name`, `time_range`, `sampling_rate`, `identity`, `get_data(t0, t1)`): `FileSource` (loader with `rate`/`__len__`/`__getitem__`), `XarraySource`, `PynappleSource` (lazy `restrict()`, no xarray intermediate). `WindowedBuffer` caches wider than the viewport. Per-plot buffers: AudioTrace/LinePlot/Heatmap(features) → `WindowedBuffer`; Spectrogram → `SpectrogramBuffer` (caches FFT); EphysTrace → `EphysTraceBuffer` (pyramid); Heatmap(envelope) → inline.

**Navigation** (`io/time_model.py` + `time_sources.py`) — session-level time metadata via `TimeSource`; `SourceCollection` is the registry. Uses only `time_range`, **never** calls `get_data()`.

### TrialTree

`TrialTree` inherits `xr.DataTree`; each trial is a child node with `attrs["trial"]`. API: `dt.trial(id)`, `dt.itrial(idx)`, `dt.trials`, `dt.trial_items()`, `dt.map_trials(fn)`, `dt.update_trial(id, fn)`, `dt.get_label_dt()`. Session metadata (trial timing, media paths, FPS, offsets) comes from `app_state.nwb_alignment`, not the tree.

### State: `app_state.py`

`AppStateSpec` is a type-checked spec (~40 vars); `ObservableAppState` auto-generates a Qt signal per variable (`current_frame_changed`, `trial_changed`, `restrict_window_changed`, `labels_modified`, `verification_changed`), exposes dynamic `*_sel` attributes, and auto-saves to YAML.

Anything defining the plot x-extent (`fixed_window_s`, `navigate_mode`, `slider_scope`) is `SCOPE_LOCAL` (per-dataset `local_settings.yaml`) — a view mode picked for one dataset must never follow the user to the next. `load_from_yaml` strips local-scope keys from the global file.

`xlim_mode` ("interval" | "fixed") is the exception: `SCOPE_GLOBAL`, a plain preference set only via the "X-limits:" combo. **Never infer it from the load path** (drag & drop, template, wizard).

**A restored path that does not exist is dropped, not restored.** `AppStateSpec.PATH_VARS` maps every saveable path setting (`video_folder`/`audio_folder`/`pose_folder`, `nwb_file_path`, `metadata_path`, `labels_import_path`, `ephys_path`, `neurons_path`, `image_paths`, `last_browse_dir`, `remote_backup_path`, `labelling_cotracker_checkpoint`) to what must exist for it — `"file"`, `"dir"` or `"any"` — and `load_from_dict` filters the YAML through `sanitize_path_state()` (`utils/paths.py`, list values filtered element-wise). Settings files travel — a copied dataset, an unplugged drive, a shared `gui_settings.yaml` — and a folder from another machine used to reach the media resolvers, which then reported a missing video/pose/audio file for *every* trial, blaming the data instead of the stale setting. Dropped values are remembered in `_unavailable_paths` and written back by `get_saveable_state_dict` while the var is still unset, so an unplugged drive does not permanently erase the folder from the file; `load_local_settings` forgets the local-scope ones first, so one dataset's dead path can never be saved into the next dataset's `local_settings.yaml`. Covered by `tests/test_unit/test_path_sanitize.py`.

### Time model + navigation

`TimeRange` (immutable: `union`/`intersect`/`contains`/`overlaps`), `TimeSource` (Protocol), `SourceCollection` (`union_range`, `intersection_range`, `session_range`, `sources_at(t)`, `trial_range`, `find_trial`, `trial_offset`; built in `data_loader.py` → `app_state.source_collection`), `RestrictionWindow` (mode `"session"|"trial"|"label"|"sequence"`), builders `build_trial_window()` / `build_label_window()` / `build_sequence_window()` / `find_closest_trial()`.

`app_state.window_bounds` (falls back to `trial_bounds`) drives every plot's x-limits; `app_state.session_time_range` is the full extent. Navigation modes ("Time slider:"): Session / Trial / Label (one class across trials) / Sequence (label pattern, e.g. `1-2-3-5`; matching in `utils/sequences.py`).

**Display basis — the one clock rule** (docs: `advanced/time_slider_trial_session.md`): `app_state.display_basis` (derived, never stored) is `"session"` iff `slider_scope == "session"` and `navigate_mode` is not label/sequence; else `"trial"`. It is THE authority on what clock the plot axis speaks. Conversions go through `app_state.to_display(trial_id, t_rel)` / `from_display(t_display, strict=)` (built on `SourceCollection.to_session`/`to_trial`; `strict=True` returns `None` in inter-trial gaps — used for label placement; non-strict snaps — used for navigation). **Never hand-roll `trial_offset + t` anywhere else.** Per-backend loaders bridge via pulled display-offset providers installed by `DataWidget._install_display_offset_provider` at every `data_loader` assignment: pynapple shifts display→absolute in trial basis, xarray shifts display→trial-local in session basis (current trial at its true session position — but **session scope is disabled for multi-trial xarray** via `NavigationWidget.update_scope_availability`, since per-trial storage cannot fill a session axis; multi-trial xarray stitching is a documented non-goal). A scope or navigate-mode change schedules a labels redraw (the basis changed, so the rectangles must be re-laid-out). Trial durations without an alignment file come from the SourceCollection trial bookmarks (`compute_trial_video_bounds` priority 2) — never straight from `union_range`, which made every "trial" window span the whole recording. `VideoSync.frame_to_time`/`time_to_frame` also speak the display clock (internal consumers that need the trial clock — extra cameras, pose overlay, label-text lookup — convert back via `from_display`). Audio files are indexed through `audio_display_offset()` (io/plot_sources.py), ephys files through `ephys_display_offset()` (plots_ephystrace.py) — one conversion each, shared by every consumer of that stream. In session basis the marker **auto-follows**: `DataWidget._follow_marker_trial` (300 ms debounce) switches to the trial under a settled marker, preserving the view and marker (`_marker_driven_trial_switch` guard in `on_trial_changed`); session-scope label clicks attribute to the trial under the click (`from_display(strict=True)`), refuse gaps and two-trial spans, and store trial-relative. Labels draw from `app_state.get_display_intervals()` — ALL trials shifted in session basis, current trial verbatim in trial basis; in session basis `update_label_plot` draws only the labels intersecting the viewport (padded) and nothing above `SESSION_LABELS_MAX_DRAWN` (zooming in brings them back; the container's `_labels_zoom_timer` refreshes the set on x-range changes). **The saved slider scope governs the first view**: `refresh_after_load` re-syncs the navigate/scope combos from the (local-settings) state and applies scope + viewport — never infer scope from the backend (the old `auto_infer_scope` is deleted; do not resurrect a "pynapple → session" rule). Covered by `tests/test_unit/test_time_basis.py` (display basis only) + `tests/test_integration/test_session_scope.py`.

### Catalog + loader: `catalog.py`

`DataCatalog` declares features, dimensions (combos) and streams; built by `catalog_from_xarray()` / `catalog_from_pynapple()`. Features are **auto-detected** (any `data_var` with a time dim; any pynapple `Tsd`/`TsdFrame`/`TsdTensor`) — no `attrs["type"]`. The "Colors" combo lists all features, filtered to names containing "rgb" via a default-on checkbox.

**A combo is named after the dim it selects from — never renamed.** movement is singular (`keypoint`, `individual`); datasets from the older wizard wrote the plural. `INDIVIDUAL_DIMS` lists the spellings most-preferred first, `catalog.individual_combo` / `app_state.selected_individual()` read whichever this dataset uses — **never hardcode one** (and never name a helper `individual_sel`: that collides with the generated combo attribute). The catalog used to rename `individual` → `individuals`, which made a selection key that was not a dim: `_sanitize_selections` counted it as pinning `individual` while the loader ignored it, leaving an extra dim free, and `sel_valid` then blew its `(time,)`/`(time, dim)` assertion mid-load. So: **a selection key either IS a dim or is inert, on both sides.** Never add a plural→singular fallback to `_selections_for_var` or `_sanitize_selections` — a rule applied on one side only recreates exactly that bug.

`DataLoader` (Protocol): `select(feature, selections, t0, t1) → PlotData`. Callers always pass `t0, t1` in **display (plot-axis) coordinates** — trial-relative for xarray always, and for pynapple whenever the active window is trial-based; loaders answer on the same axis. Selections may be overspecified — loaders ignore dims a feature lacks, like `sel_valid`.

`PanelStateMixin._sanitize_selections` guarantees **at most one free multi-value dim**, and `set_panel_control` re-applies it on *every* change (not just a feature swap) — setting a dim to "All" is the other way a panel reaches two free dims and crashes the next `update_plot()`. That guarantee covers the panel's *feature* only, so `XarrayLoader.select` pins any extra multi-value dim the **colour variable** alone carries (or one whose pinned value it lacks) to its first value — otherwise a stale saved colour/selection combo hands `sel_valid` a 3-D block. And a saved `panel_layout` is untrusted input: `MetaWidget.apply_saved_panel_layout` catches any failure applying it, discards the layout and rebuilds the data-availability defaults (`_rebuild_default_panels`) — a corrupt `local_settings.yaml` must never abort a load.

`PlotData`: `time`, `data` `(T,)`/`(T,D)`, `dim_labels`, `title`, `ylabel`, `color_data`, `changepoints` → `render_plot_data()` in `plots_lineplot.py`.

`XarrayLoader` wraps `xr.Dataset` (`update_ds()` per trial). `PynappleLoader` holds no trial state itself; pynapple objects live in **absolute session time**, and the loader bridges to display time via a **display-offset provider** (`set_display_offset_provider`, installed by `DataWidget._apply_to_state` → `_pynapple_display_offset`): queries shift `+offset` into absolute time, returned times shift back. The offset is the current trial's `SourceCollection.trial_offset` whenever the window is trial-based (trial/label/sequence scope, fixed-over-trial) and `0.0` in session scope — **pulled per call**, so trial and scope changes need no re-sync. Without a provider the loader is pure absolute-time access. The radial gate's `_candidate_bounds` also offers the session ranges shifted into display coordinates for the same reason. NWB loads via pynapple — the only direct NWB access is `_find_pose_series_names()` / `_discover_pose_keypoints()` (h5py scan).

**A pynapple feature's columns are a dim like any xarray one, named in exactly ONE place**: `_column_axes()` returns a `ColumnAxis(dim, labels)` per feature, and `catalog_from_pynapple` (combo), `PynappleLoader.feature_dims()` and `PynappleLoader.select()` all read it — including the synthetic `pose_estimation`, whose axis is its keypoints' own. Naming follows xarray so a panel behaves the same on either backend: `x`/`y`/`z` columns are movement's `space` dim (`SPACE_DIM`), objects sharing a column tuple share one dim (`columns`), a lone object gets `{name}_columns`. Three separate namings (a `_dim_map` for `select`, a hardcoded `"space"` for pose in `feature_dims`, the catalog's own rule) put combos in the sidebar that `select` never consulted — the "All" checkbox on them changed nothing, while a second combo over the same axis kept the panel pinned. **`select` resolves the column strictly under `axis.dim`** (`_pinned_column`): never scan selection *values* for one that happens to name a column — that pinned a dim the user had set to "All" via an unrelated key, and let a key for a dim the feature lacks select. `ColumnAxis.match` coerces the combo's stringified value back to the real (possibly numeric) column label, the pynapple half of `_selections_for_var`'s coercion.

### Alignment: `nwb_alignment.py`

**`.nwb` sources are read/edited directly (`edit_nwb`); `.ethograph/alignment.nwb` sidecars exist only for non-NWB sources** (`.nc`/`.npz`/pynapple folders).

`NWBAlignment(path)`: `get_stream_rate(stream, device)`, `resolve_media_path(...)` (ImageSeries path → NWB-relative → fallback folder + filename), `stream_offset_for_trial(...)`.

**Trial timing has exactly one source: the alignment NWB trials table.** For pynapple data, `_load_pynapple_dataset` reads `trials_ep` from `nwb_alignment.trials_ep` and from nowhere else — a trials IntervalSet in the data (`trials.npz`) is NEVER read for timing at load, and metadata files never carry timing (the app_state `metadata_path` setter no longer rebuilds trials from TSV timing columns). The one sanctioned bridge: the cover page (`CoverPage._maybe_offer_alignment_from_trials`) detects a trials IntervalSet in a pynapple folder that has no alignment and offers — with an explicit yes — to convert it once into `.ethograph/alignment.nwb` (`alignment_from_trials_ep` in `io/nwb_alignment.py`; the IntervalSet's metadata columns travel into the trials table). **The metadata file is purely additive**: a tabular file joined on its `trial` column; non-tabular metadata paths are ignored with a log line. There is no merge/union/conflict machinery — do not reintroduce it. Resolution priority (`_resolve_alignment`): explicit `alignment_path` wins → NWB sources use source NWB trials → sidecar TSV; non-NWB use sidecar `alignment.nwb` → sidecar TSV. `align_media_per_trial` / `align_media_from_streams` build ImageSeries from `stream_rates: dict[str, float]`.

**The trials table's filters govern navigation in every mode.** `TrialsWidget._apply_filters` writes the visible subset to `app_state.trials` (never empty — it falls back to unfiltered), which trial navigation already walks; label and sequence navigation filter their instance/match lists through `NavigationWidget._only_visible_trials` (compared as strings — label and metadata tables disagree on int vs str trial IDs) so a filtered-out trial is skipped there too. `DataWidget._on_trials_filtered` → `NavigationWidget.on_trials_filtered()` recomputes those lists and clamps the index **without navigating** — changing a filter must not fling the view to another trial.

**Metadata is edited in the trials table itself** (`widget_trials.py`) — a "Edit values on double-click" checkbox (`app_state.metadata_edit_enabled`, SCOPE_LOCAL, default OFF), an editable-combo delegate offering the values that column already uses, and an "Add column…" button. **Only the current trial's row is editable, and it is the row that is tinted** (`_apply_edit_state`, re-run on `trial_changed`): the value being typed describes what the user is watching. There is no dialog, no hotkey config and no backup file — an earlier design had all three and was too much machinery for a one-value edit; do not reintroduce them. `_applying`/`_building` guard the `itemChanged` → write path against the table's own `setItem`/flag churn.

**Metadata edits are written back to the source they were read from** (`io/metadata_edit.py`). `resolve_metadata_target()` mirrors the load priority — explicit tabular `metadata_path` → `.nwb` source/alignment trials table → sidecar `{stem}_metadata.tsv` — because writing anywhere else means the next load silently discards the edit (a sidecar written for an NWB source is shadowed by the trials table; a sidecar written for a pynapple folder only wins because `metadata_path` is then set to it). **NWB trials tables are written in append mode** (`NWBHDF5IO(path, "a")`), never through `edit_nwb`: its read-then-export path copies already-written datasets verbatim, so a changed value never reaches the file (only *new* columns do — which is why `update_trials_columns` cannot update anything). `NWBAlignment.reload()` must bracket any such write: pynwb holds the file open for reading and HDF5 refuses a second, writable handle. An NWB column keeps its dtype, so text into a numeric column raises rather than silently corrupting; `coerce_value`/`blank_column`/`fits_dtype` keep a value the type its column already is. Writes are debounced and flushed on `trial_changed` + app close (`MetaWidget.flush_pending_writes`). **An edit never re-applies the trials-table filters** — it would hide the trial being edited. Covered by `tests/test_unit/test_metadata_edit.py` + `tests/test_integration/test_metadata_edit_gui.py`.

**Drag & drop = single-trial loading** (`cover_page.py`). `classify_files()` buckets by extension; `_collect_drop_details()` shows ONE popup for unresolvable values only (npy sample rate; `source_software` for ambiguous `.h5`/`.csv`) plus an "extract audio" checkbox when the video has an embedded track (throwaway `.wav` joining the normal `audio_mic-N` pipeline). Each drop gets a **fresh** temp subdir (`_prepare_drop_dir()`, `%TEMP%/ethograph_tmp_alignment/{uuid}/`) — mandatory: throwaway `.nc` files share `local_settings` by parent dir, so a shared dir leaks the previous drop's layout. A drop resets `video_folder`/`audio_folder`/`pose_folder` to `None` first.

### Pose rendering

Two paths unified into `PoseRenderData`: `load_pose_from_file()` (movement) and `load_pose_from_nwb_direct()` (lazy HDF5 slicing). `apply_confidence_filter()` / `apply_keypoint_filter()` act on the `data_not_nan` mask; `PoseDisplayManager` displays via a `shown` mask — **filtering never recreates layers**. `nwb_pose_keys` maps camera index → pose key.

**Colour encodes ONE axis, chosen by the user** (SLEAP's model): `app_state.pose_color_by` ∈ `{"keypoint", "individual"}` (constants in `pose_convert.py`, SCOPE_GLOBAL, "Colour by" in the pose sidebar + the labelling dialog). Keypoint mode = one hue per body part shared across individuals; individual mode = one hue per animal shared across its keypoints. **Never re-derive it from the number of individuals** — that was the old auto-rule, and it silently dropped keypoint identity as soon as a second animal appeared. Text labels carry the *other* axis (`text_prop`), falling back only when that axis has one value. The same setting drives the labelling canvas, so both surfaces always agree; **there is no per-individual marker shape** (the shape alphabet was removed — colour is the only identity channel).

### Keypoint labelling + fill

Label a few frames by clicking the video, let a point tracker fill the rest — single video, 2D, one or more individuals; no training, no GPU for the default backend. **Tools ▸ Keypoint labelling…** or the Pose sidebar → `DataWidget.open_keypoint_labelling()`, one non-modal dialog. With markers, an optional **Detect** stage (`pose_detect.py`) supplies the same kind of evidence a click does, ahead of the same fill backends.

Scope: **one camera, one trial** — the dialog follows `app_state.video_path` and is keyed by frame index on that video's grid; there is no trial/camera axis, so `TrialTree` datasets are not supported here.

**The design rules for this whole area live in `docs/source/advanced/keypoint_labelling/`** — store/provenance model, fill backends, PosePAL, detection, tag printing, canvas editing, keys, dialog, points table, frame suggestion, export. **Read those pages before editing any of `gui/pose_*.py`, `dialog_pose_labelling.py`, `dialog_tag_sheet.py` or `table_filter.py`**; the rules there are binding exactly like the ones here.

### Skeleton visualization

`ethograph/skeleton/`: `PrecomputedRenderer` turns a movement poses Dataset into a Vectors layer; `SkeletonState`/`config.py` manage connections/colors/widths. Only the config layer is ethograph-specific: `nwb_skeleton_to_config(nodes, edges)` converts an ndx-pose `Skeleton` (read by `_read_skeleton_config()` → `PoseRenderData.skeleton_config`), rendered by `_display_skeleton_direct()` behind "Show skeleton". Colour precedence: `skeleton_config_override` (user-drawn) > NWB config recoloured with `skeleton_base_color`. A NaN endpoint automatically drops any edge touching it.

`dialog_skeleton_editor.py` draws a skeleton on real pose data → `skeleton_config_override`. **Anchored shapes** (`skeleton/shapes.py`): square/triangle/circle templates deforming to follow the pose; bind ≥2 control points (`ShapeAnchorDialog`) → per-frame transform (2 anchors = similarity, 3+ = affine), rendered as a Shapes layer with the frame index as first vertex coord. Shapes live under `"shapes"` in the skeleton config.

### Panels are layout instances — no per-plot-type toggles

Panels are instances created via the layout, never on/off toggles. **There is NO saved per-panel yes/no state, no panel checkboxes, no Shift+A/S/E/F/C toggles.** **Duplicates are never prevented**: dropping an already-shown source always creates another instance (removed via ✕) — never add "already shown → just reveal it" dedup.

- Created via the add-panel popup (`SourcePopup`, bottom bar ➕ / Ctrl+N): drag a source onto the plot area, or Enter for the default spot. Every panel has a ✕. Templates define layouts in the same terms. Plot-type gating (`allowed_plot_types`/`feature_ncols`) asks the **loader's `feature_dims()` first** — `app_state.ds` is `None` for pynapple data, so reading only the ds answered N=1 for every pynapple feature and hid Heatmap/Space exactly there.
- Initial visibility derives purely from data availability (`DataWidget._setup_panel_controls`): audio → trace + spectrogram, features → feature plot, neo/neurons → neural panels.
- **Panels are dock widgets** (pynaviz-style): `UnifiedPanelContainer` hosts a nested `QMainWindow` with nesting enabled; each panel is a `QDockWidget` with a slim title bar. Default is a vertical stack in `_PANEL_ORDER`, line plots at the bottom.
- **The media/plots separator drags across the whole window (~10/90 either way).** Qt clamps a separator drag at the minimum size of the widgets on each side, so every minimum in the split is deliberately a sliver: `PLOT_CONTAINER_MIN_HEIGHT`, `PANEL_MIN_HEIGHT` (every panel widget in `_make_dock`, plus the nested dock host) and `MEDIA_VIEW_MIN_WIDTH`/`_HEIGHT`. **Never raise a minimum to get a default proportion** — defaults come from sizeHints and `resizeDocks`. Covered by `tests/test_integration/test_split_ratio.py`.
- **Layout persistence is automatic; NO JSON layout files exist.** `app_state.panel_layout` (open panels + `panel_settings()` + `dock_state_b64`) is SCOPE_LOCAL → dataset `local_settings.yaml`; `app_state.window_state` (outer geometry only) → `gui_settings.yaml`. Refreshed by `MetaWidget._snapshot_layouts` (10s auto-save + close). No Save/Load layout actions. Applied via `shell.apply_dock_state_b64()`, **deferred to show when hidden** — `restoreState` must run on a visible window or Qt evicts docks created in between; later docks go through `shell.restoreDockWidget()`.

Spectrogram settings apply to all instances. When removing, stop `plot._td`.

Closing defers `remove_extra(key)` → `camera_view_removed`; pose layers/combos reset only when the LAST view of a camera closes. `add_camera(..., duplicate=True)` always creates a new view. **Anything that must follow the trial iterates the live views, never `_extra_camera_combos`** — the combos are hidden vestigial state that a popup-dropped view never enters, so combo-driven refresh froze extras on the trial that was open when they were created (right pose, stale video, because `PoseDisplayManager.update_pose()` already iterated views). `VideoManager.refresh_extra_videos()` reloads every extra from `extra_widgets` on trial change; the combos only still *create* views, for the saved `extra_cameras` restore path. Covered by `tests/test_integration/test_camera_trial_follow.py`.

The primary also takes its **fps from the probe** and its **offset from its own `stream_offset_for_trial`**, exactly like an extra — reading either from `trial_alignment` desynced it whenever the primary camera changed. `app_state.video_fps` prefers the loaded view's fps over the stored stream rate for the same reason (every time↔frame conversion goes through it). Switching the primary camera **must** rebuild `trial_alignment` first (`DataWidget._on_primary_camera_changed`). Covered by `tests/test_integration/test_camera_panel_identity.py`.

Static views are timeless, but the primary camera's pose/skeleton overlay animates via `_display_pose_on_image()` + `CameraView.set_overlay_time(t)`. Image + pose with no video works (dialog asks pose fps, image written as a static `video_cam-N` stream); image-only drops are rejected ("no time axis"). **Pose with no video and no image also works**: the alignment gets a `pose_cam-N` stream alone (no camera view), and `_build_pose_features_nc` writes the movement dataset to a throwaway `.nc` that becomes `nc_file_path` — `position`/`confidence` load as catalog features, so space/radial/line panels never require a camera.
- **Video motion is a drop-time `(time, camera)` feature**: the cover page's checkbox runs `extract_video_motion()` per camera into a throwaway `.nc` stacked on a `camera` dim (`cam-1`…, NaN-padded, needs an `individuals` coord) which becomes `nc_file_path`; the catalog then gives lineplot-per-camera and heatmap-all-cameras for free. Media/pose still come from the tmp alignment via `nwb_file_path`.
- **All line plots are equal instances**: `plot_container.line_plots`, `add_lineplot(feature=None)` / `remove_lineplot(plot)`. No `line_plot` attribute, no built-in/extra distinction. The heatmap is a fixed singleton toggled by `set_feature_view("heatmap"|"lineplot")`.

- **Feature plots render ONLY from their own `panel_state`** (`PanelStateMixin`, forked from globals via `_ensure_panel_state()`). **Never make a feature plot read `app_state.features_sel`/`get_selections()` for rendering** — that recreates cross-panel coupling. The sidebar edits the active plot via `set_panel_control()`; the global `*_sel` mirror serves only shared consumers (labels, changepoints). Changing a feature must never auto-switch lineplot⇄heatmap — only the "Feature plot type:" combo converts a panel. An "All" checkbox = absence of that dim from `panel_state["selections"]`.
- **Space plots are instances**: `DataWidget.space_plots`, `add_space_plot(feature=None, view_3d=None)` (each drop = a NEW dock, never reconfigures), removed by closing its dock. New space docks go in the shell's **top** area (never "left" — its title bar collides with the top bar). Persisted per dataset in `panel_layout["space_plots"]`, dock positions via objectNames `SpacePlotDock_{i}`. Controls are catalog-driven (Feature + "Space dim:" + X/Y/Z + one combo per remaining dim + Color) and render purely from their own combos — never global `*_sel`. **View sync** (`space_sync_views`, default on, "Sync views across space plots" in the Space settings): an interactive zoom/pan (2D, `sigRangeChangedManually`) or camera orbit/zoom (3D, inferred from input events) emits `SpacePlot.view_changed` → `DataWidget._on_space_plot_view_changed` mirrors the coordinate frame onto every other open space plot; 2D never syncs with 3D (`apply_view_state` no-ops on a mode mismatch). Programmatic range changes never broadcast, so synced plots cannot loop. **Time window** ("± Window" spin, `space_window_s`, 0 = All): only ± that many seconds of trajectory around the marker are fetched/drawn; the window slides with the marker (re-fetch only when it leaves the middle half of the fetched span, 300 ms debounce), and `_update_plot` rebuilds the plot *widget* only on a 2D/3D switch — otherwise trajectory items are swapped on the live widget (`_clear_dynamic_items`), keeping the user's zoom/camera; axis re-fitting is skipped during slides so the view doesn't chase the animal.
- **Radial (compass) plots are instances, modelled on space plots**: `DataWidget.radial_plots`, `add_radial_plot(feature=None)` / `remove_radial_plot(rp)`, own shell dock (objectNames `RadialPlotDock_{i}`), persisted in `panel_layout["radial_plots"]`. A radial plot shows ONE instant — the value under the time marker (`time_marker_updated` → `set_time`), not a time series, so it has no x-axis to link and no shared-axes section. **Offered for any feature that pins down to ONE column whose values span a full turn** (`plots_radial.angular_unit`: `max - min ≈ 360°` or `≈ 2π`, within `FULL_TURN_TOLERANCE`) — the unit is read off that span, never assumed, and never inferred from the variable's name. **The gate pins the dims first, then judges the column** (`default_selections` → every dim from `loader.feature_dims()` at its first value → `probe_angular_unit`), and the panel carries one combo per dim exactly like a space plot. **Never gate on `feature_ncols`**: a heading normally carries a `keypoint`/`individual` dim like every other feature, so requiring the raw variable to be 1-D hid the compass from exactly the datasets that have one (`angles` in Moll2025), and `feature_ncols` reads `app_state.ds`, which answers 1 for every pynapple feature anyway. The **selected shape** is still checked — anything wider than a column once all dims are pinned has no single direction. **Every candidate range is tried, none trusted** (`_candidate_bounds`: `session_range`, `union_range`, `window_bounds` — first that reads as a full turn wins): `window_bounds` alone hid the option whenever the trial held less than a full turn, while the session ranges are session-absolute where an xarray loader slices trial-relative time. **Dims are picked like everywhere else** — one combo per dim plus an "All" checkbox, and **at most ONE dim may be free** (`_on_all_toggled` unchecks the others): free, the panel draws one arrow per value with a colour legend (two keypoints, or two individuals, compared at a glance); pinned, one arrow and a readout. Arrow colours come from `app_constants.MULTIDIM_COLORS`, shared with `plot_multidim`, so a keypoint is the same colour as its line-plot trace; **past the end of the palette every arrow is drawn in one colour** with a "N individuals" legend entry — never recycle hues, which would claim the 1st and 11th individual are the same. The unit is always judged on a **pinned** column (`_pinned_selections`) — probing a free dim sees a `(T, D)` block and refuses to answer. **Which value points up is the user's**, set per instance in the sidebar's `radial` context (`radialplot_panel` hosts the active instance's `controls_widget`); `_screen_angle` also carries a clockwise flag, because an offset alone cannot express handedness.
- **Space reference geometry** comes solely from `~/.ethograph/geometries/*.yaml` (each file has a `references:` list; **one file = one selectable geometry keyed by filename stem**, all its references drawn together). `app_state.space_library_geometry` (SCOPE_LOCAL) holds the stem. Seeded on first launch by `ensure_geometry_library()` copying `ethograph/geometries/*.yaml`; it never re-seeds an existing dir, so user deletions stick. Templates set a default via `DATASETS[...]["library_geometry"]`.
- **Templates ship layouts via `local_settings.yaml`**: selecting one downloads data plus the optional release asset (`download_template_local_settings()`, never overwrites a local file).

### Console panel + derived features

Added from the popup ("Tools ▸ Python console"), it is the **one singleton panel** (`plot_container.console_panel`, `add_console_panel()` re-shows rather than duplicating): a second instance would be a second set of variables with the same names.

**The console binds what a panel *renders*, never what backs it.** Clicking a feature panel calls `bind_panel(plot)` → `loader.select(plot._effective_feature(), plot._effective_selections(), *plot.get_current_xlim())` and binds the resulting `(T,)`/`(T, D)` array to the feature's name, plus `t` (its time vector, so rates come from the data: `np.gradient(pos, t, axis=0)` is per second). **Never widen this to the underlying object.**

Numpy, not xarray: `TracedArray` (`io/derived.py`) *is* an `np.ndarray` and `__array_ufunc__` records the expression graph. Every assigned name becomes a feature via `DerivedLoader.register()`, as a **recipe** (all-ufunc: re-evaluated per window/trial with the source's selections pinned) or a **snapshot** (anything that left the ufunc world — frozen to its time vector). A recipe may name an earlier derived feature, so `DerivedFeature.evaluate` resolves roots through the `DerivedLoader`, not its base. Values that aren't added get a reason (`_rejection_reason`), including the sequence-of-arrays case `np.gradient(pos)` with no `axis` produces.

**`stack(sin, cos)` / `stack(sin=..., cos=...)` gets several curves in ONE panel**: a `(T, D)` feature whose column names become `dim_labels` (positional labels come from `TracedArray._eto_name`, stamped by the console on assignment). Its columns are exposed as a dim named `DERIVED_COLUMN_DIM` (`"Dimension"`), and `select` honours `{"Dimension": "sin"}` — **this is what makes a derived feature usable as a space plot**, which picks each axis with `{space_dim: value}`. Plain multi-assignment still makes two separate 1-D features; do **not** add tuple-unpacking magic.

Commands: `features()`, `forget('name')`, `clear` / Ctrl+L (bare `clear` works via `_ClearCommand.__repr__`), `clear(all=True)`. Help lives behind the `?` toggle (`_HELP`), **never printed** — the transcript is the record of the user's work.

**Derived features live for one trial.** `trial_changed` → `ConsolePanel.reset_for_trial()` drops every binding and derived feature; carrying a recipe forward would describe the previous trial's setup. `MetaWidget._close_panels_for_missing_features()` then closes any panel on a feature that no longer exists, so nothing is left permanently blank.

**The console rebinds on `plot_container.panel_content_changed`, NOT `active_changed`** — the latter never fires on sidebar feature edits, and a click can fire both, so binding there too would double-bind. Emitted from every feature panel's `plot_clicked`, from `DataWidget.apply_panel_control`, and from `MetaWidget._activate_panel` (a just-created panel has no click behind it). **That signal is the console's ONLY rebind channel** — `_on_active_panel` must never call `bind_panel` as well, or a click that also changes the active panel binds twice.

**Every bind prints `name: shape (T, D) [pinned] t = …`.** Clicking a panel is a question — "what am I holding now?" — so a re-click on the same panel answers again; there is no "only if it changed" suppression (that made a click look like it had done nothing).

`DerivedLoader` wraps the real loader **at every `app_state.data_loader` assignment**, forwards everything it does not define, and appends derived names to the wrapped catalog (restoring from a captured base list on `forget()`, never by filtering the live one).

### Plot system

All plots inherit `BasePlot` (pyqtgraph `PlotWidget`): time marker, x-range management, click handling, axes locking. `UnifiedPanelContainer` holds all panels and links x-axes.

### Video sync

`NapariVideoSync.frame_to_time(frame)` / `time_to_frame(t)` apply `time_offset` AND the display offset — they speak the **display clock**. All widgets use these — **never raw `frame / fps`**. Consumers needing the trial/video clock (extra cameras, pose overlay time) convert with `from_display`. Video decode stays clipped to the current trial (`_trial_clip`, whose frame math is the shared `trial_frame_window()` in `io/time_model.py` — also used by pose slicing, never duplicated).

**Playback over a cold decode worker steps synchronously until it warms up — never wait, never free-run.** A freshly spawned pynaviz worker (trial/camera switch, ~2 s on Windows) drops async seeks, so a playback clock started against it rendered nothing and jumped to the segment end. All playback paths seek via `VideoSync._seek_playback_frame`: while `CameraView.decoder_ready()` is False (a `-1` sentinel in `shared_index`, armed at plot spawn, overwritten by the worker's first served frame) each tick decodes its frame synchronously in-process — every tick renders, zero start-up gap — plus one async request per tick so the waking worker's first serve is current; the tick after it answers hands over to pure async. `play_segment`'s **initial seek is async too**, exactly like regular Play (space): the old synchronous start-frame decode blocked the GUI on far seeks, which was the gap felt between navigating and playback starting. Two rejected designs, don't resurrect them: **wait-for-readiness** (probe + deferred clock) stalls on the video's keyframe-index scan far longer than needed, and a **fixed start delay** neither covers a real cold spawn nor gives smooth frames. The "Auto-play on navigate" checkbox is backed by `autoplay_on_navigate` (SCOPE_GLOBAL — a reviewing habit, not a dataset property). Covered by `tests/test_unit/test_video_sync_ready.py` + `test_autoplay_state.py`.

**Reloading the same file must never rebuild the `PlotVideo`.** `CameraView.set_video()` reuses the loaded plot when `_video_path` is unchanged (trial change, camera re-apply) and only re-clips `start_frame`/`end_frame`/`time_offset`; only a genuinely different decode path (proxy swap, other camera) goes through `clear()`. Each `PlotVideo` owns a **spawned** pynaviz worker that must re-import `av`/`pygfx`/`pynapple` (~1.5–2 s) before attaching to the parent's shared memory, while `PlotVideo.close()` waits only `join(timeout=2)` before dropping the parent's handle — which destroys the mapping on Windows — so a close-then-create cycle kills the new worker with `FileNotFoundError: [WinError 2] … 'wnsm_…'`. `update_video()` therefore drops only the `VideoSync` (`_teardown_primary_sync`); `_cleanup_primary_video` (= teardown + `view.clear()`) is for genuinely unloading the video, and any aborted setup must clear the view itself. On the reuse path the renderer handlers and the `_update_extra_objects` overlay hook are **not** re-registered (they survive with the plot); `_detach_load_state()` drops the per-load state — labelling mode and pose overlay — that `clear()` would have. Covered by `tests/test_integration/test_video_reload.py`.

### Labels

**Storage:** TSV (`{name}_labels.tsv`) alongside the `.nc`. Columns: `onset_s, offset_s, labels (int), individual, trial, human_verified, changepoint_corrected, prediction_source, n_samples`. **`onset_s`/`offset_s` are canonically trial-relative** — written and read as-is, with no basis detection anywhere. **A saved TSV carries no comment header**: a leading `# ...` line makes a plain `pd.read_csv(path, sep="\t")` parse it as the column row and hand back a one-column frame, which broke every analysis script reading these files. `load_labels_tsv` still passes `comment="#"` so the files written during the short life of the `# time_basis:` header keep loading. The session clock is not lost: `enrich_labels_df` writes `trial_onset`/`onset_global`/`offset_global` alongside whenever the alignment knows the trial start, so both clocks are in the file. Do not reintroduce basis inference, a basis header, or a dialog asking which clock a file is in. Label names in `mapping.txt`. Legacy `.nc` embedded labels auto-migrate on first load. In memory: `app_state._all_labels_df` (all trials, trial-relative) and `app_state.label_intervals` (current trial); `get_display_intervals()` is the read-only axis-clock view for drawing/hit-testing. Per-trial metadata as columns rather than a dict.

**The close prompt asks the file, not the flag.** `app_state.changes_saved` is cleared by anything label-adjacent, so it over-reports — sessions that only edited trial metadata were still asked to save labels. `MetaWidget._check_unsaved_changes` calls `app_state.labels_dirty()`, which compares `_all_labels_df` against `labels_file_path()` on disk via `labels_equal` (canonical `TSV_COLUMNS` only, order-insensitive — a saved file's computed extras like `duration`/`onset_global` are not content). `labels_file_path()` is also what `save_labels` writes to, so the two can never drift. Covered by `tests/test_unit/test_labels_dirty.py`.

**Per-plot-type rendering:** `app_state.label_overlay_modes` maps plot type key (`lineplot`, `audio`, `spectrogram`, `heatmap`, `ephys`, `neo`) → `"full"|"bottom"|"none"`, applied to every instance of that type — no visibility hierarchy. Defaults in `DEFAULT_LABEL_OVERLAY_MODES`; edited via `LabelsPerPlotDialog`.

**Labels on new panels:** any path creating/showing a panel must end with `plot_container.schedule_labels_redraw()` — deferred because it must run AFTER content render, or "bottom"-strip rectangles (positioned from the y viewRange) are invisible. **Never emit `labels_redraw_needed` synchronously from a panel-creation path.**

**Predictions:** per-trial `.npy`/`.pickle`, shape `(T, n_classes)` → confidence via `1 - normalized_entropy`, labels via `argmax`. Confidence stays in memory, never stored. Dotted confidence curve on by default, gated per feature plot by `show_predictions` in `panel_state`.

**Crowsetta:** `EthographSeq` registered at import; the export adapter converts int→string via the mapping. Internal storage stays integer-based.

**Top-bar File menu:** "Import labels…" / "Import predictions…" / "Export labels…" each borrow their own I/O sub-panel (`IOWidget.restore_subpanel()`). No "Load data…" — data loading happens only on the cover page.

### Widget orchestration

`MetaWidget` creates all widgets and wires signals; `DataWidget` is the central orchestrator. Flow: `NavigationWidget` → `trial_changed` → `DataWidget.on_trial_changed()` → everything else.

**Context-sensitive right sidebar:** the sections shown per plot type are defined solely by `_CONTEXT_MAP` (+ `_CONTEXT_TITLE`) in `gui/right_context.py`. `MetaWidget._build_context_panel()` borrows the real group widgets from `DataWidget`/`PlotSettingsWidget`/`NavigationWidget`; `_on_active_panel()` swaps context on panel click (only for `_CONTEXT_KINDS`; raster keeps the current sidebar). **A panel click is never a silent no-op**: `ActivePanelManager.set_active` re-emits `active_changed` even for the already-active panel, because the context swap is suppressed while zen mode is on or the Labels/Navigation section is open — with the old early-return, a click on the still-active panel after those states could never un-stale the sidebar. Those suppressors also re-sync on lift (`_sync_context_to_active`, called from the `MetaWidget._expand(0)` override and `zen_mode_changed` → off). `ephys` → `phy` section (`EphysWidget.traceview_panel`); `neo` → `neocontrols` (`PlotSettingsWidget.neo_controls_group`, editing the active panel via `set_active_neo_plot`). Neither includes the `shared` autoscale/lock-axes group. The **Neural** menu keeps only "Open interactive PSTH…" and "Firing rates…".

**Guarded shortcuts are DISABLED while typing, never a no-op.** Every global shortcut (`shell.bind_shortcut`) has `Qt.ApplicationShortcut` context, so an enabled one consumes the key press before the focus widget sees it — the old "guard" (callback returns early while a text field has focus) still swallowed the key, which made Space untypable, ←/→ unable to move the text cursor, and ↑/↓ dead in the add-panel popup's filter box (`SourcePopup.eventFilter` never ran). `EthographMainWindow._sync_guarded_shortcuts` (on `QApplication.focusChanged`) toggles `setEnabled` for the shortcuts bound with `guarded=True`; `typing_in_text_field()` in `gui/shortcuts.py` decides. Never re-guard by early-returning inside the callback. **Keys a text editor owns are guarded automatically** (`_TEXT_EDITING_KEYS` in `gui/shortcuts.py`, applied by `bind` whatever the call site passes): unguarded, `Ctrl+V` both swallowed the paste into a metadata cell and ran the action behind it (`Ctrl+V` = mark trial human-verified), so a metadata-only session ended with the “save your labels?” prompt on close. Covered by `tests/test_unit/test_source_popup_nav.py`.

**Neo trace panels are dynamic instances, one per stream/modality.** `_DYNAMIC_PANEL_SPECS["neo"]` makes `add_panel("neo", stream_name=…, channels=…)` create an instance per modality (collection `plot_container.neo_trace_plots` — there is NO `neo_trace_plot` singleton). `add_panel` calls back into `DataWidget.configure_neo_plot(plot)` to load the stream and restrict to `plot.neo_channels` via `set_custom_channel_set` (`None` = all). The popup lists one "Neo (…)" per stream (excluding the Phy/kilosort stream); dropping opens `ChannelSelectDialog`. `on_kilosort_loaded()` drops Neo panels duplicating the Phy stream; `refresh_neo_panels()` re-renders on trial change.

**Neo and Phy trace panels are NOT auto-loaded (heavy).** Load only resolves the Phy stream (`_ensure_default_ephys_stream`) and pre-wires the source (`configure_ephys_trace_plot`, hidden). Both are added on demand from the popup — "Ephys (Phy-like viewer)" (kind `"phy"`, shown when `MetaWidget._phy_available()`) and one "Neo (…)" per stream. `_add_phy_panel()` re-shows the Phy singleton so ✕-then-re-add works. `refresh_source_popup()` repopulates on each open and after Kilosort load.

### Neurons + ephys

Two paths → `nap.TsGroup` + cluster table: **Kilosort folder** (`.npy` + `cluster_info.tsv` + raw `.dat`; full features — probe map, waveforms, raster) and **Pynapple file** (`.npz`/`.nwb`, `data["units"]`; raster only). State: `app_state.neurons_path`, `app_state.has_neurons`, `EphysWidget._neurons_source`.

**Kilosort has two index spaces**: site index (0..n_sites-1, indexes `channel_positions.npy`) vs hardware channel (`channel_map.npy`, can exceed n_sites; the `ch` column of `cluster_info.tsv`). **Always index `channel_positions` by site index.**

### Changepoint correction

Bridge pattern: intervals → dense → correct → intervals. Kinematic CPs stored dense `int8`; audio CPs as onset/offset float pairs.

## Dataset Structure

- NetCDF with trials. Time coords: anything containing `time` (`time`, `time_aux`, …).
- Every `data_var` with a time dim is a feature — no `attrs["type"]` needed. Changepoints still use `attrs["type"] = "changepoints"`; colour vars are identified by "rgb" in the name.
- Media/session metadata: `.nwb` sources read directly; non-NWB read `.ethograph/alignment.nwb`.
- Labels live in `_labels.tsv`, not the `.nc`.
